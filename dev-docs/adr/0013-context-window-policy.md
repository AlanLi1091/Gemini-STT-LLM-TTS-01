# ADR-013：有限上下文窗口与计数降级

## 背景与授权

2026-10-06，用户确认 P0-1 第一步修订方案及 Claude 五项实现补充。长期 Web / Discord 会话原先每轮发送全部持久化历史，输入成本随历史增长。本步只限制模型视图，保留完整仅追加日志与 ADR-012 幂等语义；Discord 重置 / 归档锁为第二步，尚未授权实施。

## 预算与轮次

- 默认输入预算 8192 tokens、最多 20 个历史轮次加本轮输入、生成上限 8192（包含思考 tokens，不是可见正文额度）。配置范围与环境变量见 deploy/README.md。
- 一轮从 user 开始，包含其后连续 assistant；连续 user 分别成轮。先忽略历史 system 与没有前置 user 的孤立 assistant，窗口不以 assistant 开头。只选最近连续轮次，整轮删除最旧历史，不切单条正文。
- 服务端窗口层排除所有传入的 system 消息，只把 GEMINI_SYSTEM_INSTRUCTION 配置给 Gemini 适配器；不改变 core resolveSystemInstruction 原有合并行为，现有正向测试保留。日志中的 system 不删除 / 修改，P1-1 的输入角色限制与关闭无状态模式仍待独立授权。
- 构造窗口发生在新输入写入之前。已存在的失败输入从历史尾部拆出，作为本轮输入仅出现一次。先判断完成回放；回放不选窗口 / 计数 / 调用模型。超限新输入不落盘，旧失败输入超限不删除。

## 本地估算与精确计数

- 本地基数为256固定开销，加配置系统指令的字符单位，加每条消息的字符单位与32开销；ASCII每字符0.9，CJK / 假名 / 韩文1.5，其他Unicode按UTF-8字节，乘默认系数1.25并向上取整。这是工程估算，不是 tokenizer 或数学上界，不保证所有输入必定不低估。
- 候选先限制历史轮数；完整候选本地估算不超过预算80%且满足宽松字节上界时直接生成。边缘区保留全部候选，先对最多最近8个历史轮次加本轮输入取样；只按计数正文总UTF-8字节不超过输入预算32倍做宽松预筛，不提前按保守估算硬裁。最小本轮超过该字节上界时拒绝，不切正文。精确计数只覆盖对话内容，另加配置系统与固定开销的本地估算。
- 最多两次计数 / 选择；进程级独立默认 20 次 / 分钟，每次默认 3 秒，透传 AbortSignal 并用本地超时竞速兜住不响应中止的计数器。计数不额外扣生成预算；计数 429 只暂停自己的预算。
- 第一次计数获得对话token / 字符单位比率（可以低于1）；使用全部保留候选选择最近连续整轮，拟合到95%预算并保持宽松字节界限，允许加回未参与取样的轮次。候选变化后第二次精确核验，只有精确结果加系统估算不超过输入预算才直接使用；不再对第三个候选继续计数。用户取消不继续生成，鉴权错误直接反馈。
- 第二次计数失败 / 预算耗尽 / 核验超限时，优先保留首次已精确验证安全的取样。没有已验证取样时，从完整候选收缩到本地估算不超过80%的窗口，并禁止返回刚被精确确认超限的同一候选；最小本轮仍无法容纳或已精确确认超限时返回CONTEXT_LIMIT。无计数能力时本地窗口记忆可能明显缩短，无法承诺实际利用率。没有全量历史回退、自动摘要或精确token数学保证。
- 实际回复的 promptTokenCount 用于提高下一次估算系数；系数只升不降、最高 4，无效用量忽略，只保存于 policy 内存并记录不含正文的调整日志，进程重启恢复 1.25。Mock 不提供精确计数，走本地路径。

## SDK 兼容证据

本机已安装 @google/genai 的 dist/node/index.mjs 中，countTokensConfigToMldev 明确拒绝 systemInstruction / tools / generationConfig。离线真实 SDK 探针用占位 Key 并拦截全局 fetch：携带 systemInstruction 的 countTokens 在发起请求前抛出“only supported ... not in Gemini Developer API mode”，fetch 次数为 0。没有调用真实 API 或打印密钥。

据此 GeminiChatAdapter.countTokens 只发送 model、contents 和 abortSignal，不携带系统指令；配置系统文本由窗口层估算并加计。SDK Mock 回归明确核对请求结构。此证据确认本地 SDK 行为，不冒充 VPS SDK 版本或上游在线实测。

参考：[Gemini token 计数](https://ai.google.dev/gemini-api/docs/tokens)、[GenerateContent 思考与输出上限](https://ai.google.dev/gemini-api/docs/generate-content/thinking)。

## 输出截断与错误

- send / stream 检查首候选 MAX_TOKENS；有非空白正文时在最终内容末尾附加一次“回复已达到长度上限，内容已截断”，返回 done / usage，并持久化同一正文。重复流标志只提示一次，不自动续写。
- 提示属于保存正文，因此以后窗口中的模型会把它视作自己先前说过的话，这是本次明确接受的取舍，不新增前端元数据渲染体系。
- 任意结束原因的空或纯空白模型正文均返回固定 MODEL_ERROR，不产生成功空回复，也不保存新空 assistant；MAX_TOKENS 保持既有专用文案，详见下方K1修订。非成功流的部分正文持久化仍属 P1-4，本步不处理。
- 输入超限使用既有 SSE error 结构与新增 CONTEXT_LIMIT；Web / Bot 都使用固定缩短输入提示，不透传任意服务端原文。

## Claude C1 / C2 复核修订（2026-10-06）

原实现在计数前按1.25倍UTF-8字节硬裁且不能加回，导致长回复只保留一两轮；本轮按用户确认的十文件计划修正选择顺序与字符分类。观测比率只用于当前请求拟合，不降低持久校准系数，校准仍仅内存只升 / 上限4。

新增9项回归，33/33文件、364/364用例通过。三组近似计数夹具（不是Gemini在线实测）结果：中文50字输入 / 800字回复保留8轮，7190模拟tokens（含系统预留）、87.8%，计数1次；中文300 / 300字保留11轮、7220、88.1%，2次；英文200 / 3000字符按0.25token/字符保留9轮、7570、92.4%，2次。夹具均验证>=70%且不超过预算、顺序连续、本轮只一次；另覆盖加回全部20轮、第二次计数失败 / 次数耗尽保留已验证取样、超限候选不回退为同一窗口与约2500中文字本地可用。

C2降级仍是保守取舍，部署说明明确计数不可用时记忆可能变短。本轮没有更改计数SDK兼容路径、超时 / 取消、P0-2幂等语义或Discord重置范围。


## P1-7：计数预算来源保留（2026-10-12）

- 生产装配的计数预算保留全局默认20次 / 滚动60秒，新增Web保留默认8；所有Discord会话合计最多12，Web可使用全部总额度。来源同生成预算，来自持久化origin，旧会话默认web。
- 来源作为select / count调用参数传递，不设置共享可变当前来源，交错计数保持各自来源；来源守卫和总守卫全部允许才扣额。低层测试仍可显式注入原RequestBudget，默认来源参数为web。
- 计数阶段429暂停所有来源的计数预算（沿用60秒），不暂停生成；额度耗尽 / 暂停仍使用既有本地降级或安全取样。两次计数上限、候选选择、估算、计数鉴权及取消语义不变，未修复C3–C5。
- 生成准入位置不变，窗口选择中已经消耗的计数不因后续生成预算拒绝而回滚。本地保留不是账户配额保证，不查询真实RPM / TPM / RPD。

## K1：所有结束原因下的空模型正文（2026-10-12）

- Gemini send / stream 对任何结束原因（含STOP、SAFETY、MALFORMED_FUNCTION_CALL、RECITATION、OTHER、缺失原因）的空或纯空白正文返回MODEL_ERROR，固定提示「模型未返回有效正文，请稍后重新提问。」；MAX_TOKENS空正文仍用既有长度上限提示，有正文的截断提示不变。空输入不发上游的原适配器快捷路径保持不变。
- 会话 / 非会话流源都在完成chunk校准前检查正文；会话流源在storage阶段之前拒绝空done，不调用appendAssistantResponse、不发done，模型阶段固定错误经safeStreamError下发。不会校准失败空回复，不暂停生成预算；已消耗生成额度不退还。
- 已追加user输入保留，模型失败后finally释放锁，同requestId重试复用输入并重新生成，成功回复仍可幂等回放。P1-2超时 / 取消、P1-3日志脱敏、P1-7来源保留与429暂停语义保持。
- 历史空assistant不删除、不改写，本步窗口选择不额外过滤；原user起始轮次配对与预算规则保持，ADR-012已有完成回复（含历史空回复）的回放保持原样。本步只防止新增空回复，历史空回复回放仍可能产生空气泡或Bot静默；如需改变须另行指派。
- 错误元数据只传finishReason；日志仅模型阶段输出已知枚举，未知值归OTHER、字段缺失时省略，不记录正文或任意结束说明。Bot保留既有MODEL_ERROR固定反馈。
- SDK Mock、其他adapter空done、隔离JSON、同标识重试 / 回放、历史窗口 / 日志不改写与脱敏回归通过；新增9用例，36/36文件471/471用例、根 / 四包类型检查和三构建通过。未部署、未调用真实上游 / Discord / 会话数据。
