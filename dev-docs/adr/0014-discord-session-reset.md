# ADR-014：Discord 会话重置与共享归档锁

## 背景与授权

用户确认 P0-1 第二步文件计划：为管理员提供频道重置入口，复用已有“归档后解析新会话”，并使生成 / 归档 / 重置共享会话锁。仅本机代码与隔离测试，不部署 VPS；C3–C5 和其他审计任务仍未授权。

## 入口与权限

- 在指定频道直接提及Bot，沿用 normalizeMessage 的消息过滤与提及清理；清理后正文首尾去空白、精确等于 `/reset` 才分流。大小写 / 额外参数仍普通聊天，不注册Slash Command。
- DISCORD_SESSION_ADMIN_IDS 为Bot环境配置的逗号分隔用户ID；格式沿用项目17–20位约束，并要求无前导零、正值且在uint64范围，重复去重、非法 / 空项启动拒绝。空配置默认禁用命令。
- 权限核对在调用后端前进行。拒绝提示不调用chat或reset；所有请求仍通过既有频道FIFO、冷却及容量控制，重置等待前一轮全部回复发送完毕。返回消息继续抑制所有提及。

## 协议与幂等目标

1. Bot解析频道当前sessionId，再POST `/api/discord/sessions/reset`，请求包含guildId、channelId、该明确sessionId。
2. 端点复用loopback / 无Origin保护，校验字段格式与目标持久化origin，拒绝Web / 跨频道 / 不存在目标；未引入通用API鉴权，可信Bot校验管理员，网络边界依赖当前私有部署，P2仍是公网前置条件。
3. 共享服务锁内归档目标，然后复用storage.resolveDiscordSession，返回 `{ archivedSessionId, sessionId }`。不另写绑定新建逻辑，旧消息不删 / 不改，其他频道不受影响。
4. 重复同一明确旧目标只会重读幂等归档并解析现有新关联，不会归档替代会话。重复用户命令会重新解析当前目标，属于新重置意图；Bot消息ID全链路幂等仍为另行任务。
5. 新ID格式、与旧ID不同、archivedSessionId匹配都校验通过后才反馈“已重置”。命令不发送到模型或持久化消息，生成 / 计数预算不因重置而清空。

## 锁与失败语义

- server/index.ts 创建唯一SessionService供API路由和环境流工厂共用；工厂支持显式服务，旧sessionStorage注入保留兼容，但不允许同时传两者。
- 生成持有原会话锁；archiveSession与resetDiscordSession在相同锁上同步尝试获取，冲突立即失败而不等待 / 强制取消，finally释放。重置调用storage.archiveSession避免再次获取同一锁。
- Web归档和重置冲突均返回HTTP409与REQUEST_CONFLICT，聊天仍为既有SSE error。Bot同时认识HTTP409与SSE冲突码并固定提示；不自动重发。
- 归档失败旧会话不变；归档已成功但resolve失败，旧目标已归档而绑定可能仍指向旧目标，下次已有resolve路径创建新会话。不是跨文件原子事务，不回滚已保存日志。
- Bot重置整体超时 / 取消有本地竞速兜底，解析迟到不会继续POST重置；已发出的服务端操作可能完成，失去确认时不能声称失败无副作用，固定反馈“未确认完成”。HTTP取消不回滚归档。
- 服务端上游超时与挂起锁恢复仍属P1-2；部分回复持久化仍属P1-4；JSON损坏绑定等仍属P1-5。本步不提供强制解锁。
