# ADR-012：请求幂等与失败重试语义

## 背景与授权

2026-10-06，用户单独授权 P0-2 修复，确认文件计划与 Claude 审查补充。原会话接口在调用模型前追加输入；Web 失败重试会再次追加相同正文，污染上下文。本决策补充 ADR-005 的身份 / 仅追加约束与 ADR-007 的 SSE 请求契约，不实现编辑、分支或通用重新生成。

## 请求与身份

- 会话请求可携带稳定 UUID `requestId`；携带时必须同时提供非空 `sessionId`、恰好一条非空白 `user` 输入。UUID 校验版本位 1–8 与 RFC variant，服务端转为小写；输入正文按原值核对，不按内容去重。
- Web 创建输入时生成 UUID，首次请求和失败重试复用该 ID；优先 `crypto.randomUUID`，不支持时使用 `crypto.getRandomValues` 生成 UUID v4。
- 持久化输入的 `id` 与 `requestId` 相同；完成回复使用独立 UUID `id`，并携带同一 `requestId`。这是请求关联元数据，不是消息树或修改日志的机制。已有消息不删除、不覆盖、不补写元数据。
- 旧文件没有元数据仍可读取；未携带标识的旧 Web / Bot 请求保留原追加路径，本次不保证其重发幂等。旧客户端在修复前已产生的重复日志不自动清理。

## 状态与判断顺序

| 状态 | 行为 |
| :--- | :--- |
| 输入标识不存在 | 追加一次输入，调用模型 |
| 输入已存在、无回复且无进行中请求 | 正文必须相同、输入必须仍在日志末尾；复用输入，重新调用模型 |
| 回复已保存 | 在正文核对后、末尾检查前返回已保存回复；发送单个 `done`，携带保存的用量，不调用模型或再次写入 |
| 同会话正在生成 | 立即返回 `REQUEST_CONFLICT`，不等待、不追加、不调用模型 |

没有时间意义上的“过期”：只有未完成输入不在末尾、内容与标识冲突、会话归档等条件拒绝。已完成请求即使后面已有其他轮次仍可回放；归档会话维持不可再发起会话请求的既有约束。

会话锁检查先于读取持久化状态：同会话存在活动生成时，包括已完成请求的回放在内也立即冲突；取得锁后，必须先查已保存回复，再检查未完成输入是否在末尾。

## 并发与存储防线

- `SessionService` 持有进程内会话锁，覆盖所有经会话流源的请求，包括无标识请求与 Bot。锁在首次异步操作前同步获取，直到流结束 / 出错 / 上游中止清理的 `finally` 才释放；不把超时清锁作为策略。
- 停止后立即发送可能在旧上游完成退出前收到冲突。Web 展示固定安全文案并保留手动重试入口，不自动重发；Bot 继续使用既有后端失败反馈。
- 持久化写入队列内，同 `requestId` 同角色不得出现第二条消息，分别防止重复输入与重复回复；关联回复写入时必须仍对应日志末尾的 `user` 输入，归档后拒绝关联写入。检查与追加在同一串行写事务中。
- 部署继续遵循 ADR-011：单 Express 进程、单存储写入实例。内存锁与 JSON 写队列不是跨进程 / 多实例锁，不扩展到多写者部署。
- 模型预算在回放判定后、输入写入前获取：回放和请求冲突不消耗模型预算，超限不追加新输入；上游 429 继续暂停预算。

## 错误与协议

结构不合法返回 HTTP 400；已进入 SSE 的业务冲突使用 `error` 事件与新增 `REQUEST_CONFLICT` 错误码、固定消息。`chunk` / `done` / 心跳和不支持 `Last-Event-ID` 断点续传的契约保持不变；完成回放不重放历史 chunks。

## 范围与验证

- 不处理 P0-1 上下文预算、P1-4 部分回复持久化、P1-1 的其他角色 / 无状态路径；用户停止后再发送仍可能留下连续 user 输入，这不属于本项回归失败。
- Bot 请求标识接入仅登记为未授权后续工作，Discord Snowflake 不能直接通过本次 UUID 契约，未来需单独决定映射或拓展契约。
- 数据流测试覆盖失败重试、完整回放（含后续轮次）、内容 / 顺序冲突、全会话锁、停止后立即重发及重启恢复；存储测试覆盖原子防重复输入 / 回复与旧文件兼容；HTTP / Web 测试覆盖真实本机接口与 Mock 交互，不调用真实 Gemini / Discord 或 VPS。
