# ADR-007：流式响应统一纳入 ChatAdapter 契约

## 背景

LLM 对话打字机体验必须依赖流式传输，且需要支持用户中途打断。

## 决策

1. adapter 统一 `stream(): AsyncIterable<ChatChunk>` + `AbortSignal` 中断。
2. 注明 ADR-005“禁止原地修改”限定于编辑重发场景，流式中末条消息 content 逐 chunk 更新不违反，日志数组仍仅追加。

## 影响

统一 Mock 与真实模型的流式协议；打字机动效与 token 统计接口规范化。


## Phase 5 搜索最终事件目标契约（2026-10-13）

[ADR-015](0015-external-search-architecture.md)将模型生成与搜索编排分离；本节是 Task 20–21 的目标契约，本步未修改 ChatChunk 或运行时代码。

- 领域流的最终成功事件及对外 SSE done 在 content / usage 之外携带可选来源元数据与受约束搜索状态，普通轮次及旧消息缺字段按无搜索来源兼容；由服务端编排层装配，不要求模型 adapter 生成来源 URL。
- chunk 仍只承载模型正文增量及累计正文；来源列表只在最终保存成功后随 done 交付，由 Web / Discord 根据校验元数据显示摘要与链接。心跳、错误码和不支持断点续传的语义不变。
- 最终非空正文、搜索状态与来源一起追加保存；保存失败不发 done。完成回放发送单个 done，带原状态 / 来源，不重放 chunks、不重新搜索或重复计费；刷新读取相同元数据。
- 降级说明独立于模型正文；不能作为有效正文绕过 K1。取消、超时或中途失败不保存半截 assistant / 成功来源；D12 已定 Web 移除未完成临时回复、保留 user 同 requestId 重试。P1-4 / R3 的 UI 与持久化实施仍须另行授权。
- AbortSignal 贯穿搜索、计数与生成，用户取消不转普通生成；迟到上游结果不发送成功事件、不落盘。所有新增错误及搜索失败原因只使用 safeStreamError 固定文案与本地受约束枚举。
