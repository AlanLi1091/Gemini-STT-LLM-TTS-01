# ADR-015：显式外部搜索、来源契约与安全边界

## 状态、依据与授权

2026-10-13（America/Vancouver），Task 19 Step 3 架构定案。用户确认八文件计划；本步仅交付文档，下面是 Task 20–22 的目标契约与验收要求，不表示运行时代码已经实现。

依据：[Task 19 预研第 10 节](../research/phase5-search.md#10-step-2-裁决清单2026-10-12part-b裁决完成)的 U1 / U2、D01–D14，以及[第 11 节](../research/phase5-search.md#11-claude-复核补充2026-10-12)的 N1–N4。N1 / N2 优先于早期 D04 / D05 中共享校准与完整 URL 注入的描述。供应商用途许可及中文质量 / 生产延迟仍待补证据，产品裁决不能代替合同许可。

## 1. 搜索层与入口（U1 / U2、D01 / D02 / D03、D13）

- 采用与模型无关的外部 SearchAdapter 边界，Express 承载搜索编排；选定 Tavily basic，经原生 HTTP 接入，不新增 npm 依赖。保持 ChatAdapter 的模型生成职责，不启用 Gemini grounding、模型自主搜索或额外查询生成调用。
- 固定供应商 HTTPS 端点，basic、auto_parameters=false、chunks_per_source=1、最多 3 来源，关闭 include_raw_content / include_answer，不调用 Extract。不抓取结果网页、解析跳转或生成服务端预览，不把供应商生成答案当模型正文。
- Web 逐轮“联网搜索”开关默认关闭；Discord 直接 @Bot 后正文 `/search` 加空格及非空问题触发，不注册新的 Slash Command。沿用 ADR-014：先分流精确 `/reset`；`/reset xxx`不扩展重置，`/search /reset`只是问题。孤立 `/search`提示补问题，不消耗搜索或模型额度；普通文本不自动搜索。
- 共享请求增加显式 search 意图，旧请求缺字段按 false。只外发去命令后的当前问题，最多 500 Unicode 码点；超长要求缩短，不静默截断。不外发历史、系统指令或 Discord 身份字段；查询本身可能包含个人信息，不能承诺自动识别全部敏感内容。
- 搜索 Key 仅配置于 server.env，不进入 Bot、浏览器、Git 或日志。Web 开关说明和 Discord 使用说明告知查询交给 Tavily，频道回答 / 来源会对成员可见并由 Discord 留存，不承诺 ZDR。

## 2. 来源过滤、模型输入与展示（D04、D07 / D08、N2）

- 每轮最多 3 条校验通过的结果；单条摘要最多 100 Unicode 码点（含标点），标题最多 120 码点，完整 URL 最多 2048 字符；响应边读取边限制为 256KiB，不能先无限读取再裁剪，读取 / 解析也受搜索期限约束。
- 结果链接仅允许 http / https，拒绝凭据、控制字符和无法解析的 URL；真实域名从 URL 解析，不接受标题伪装目标。完整链接只作为来源元数据，Web 纯文本标题 / 摘要加安全链接，不能直接渲染供应商 HTML / Markdown。客户端仍须独立执行协议白名单与安全渲染，持久化数据不自动可信。
- **N2**：模型只接收编号、纯文本标题、真实域名和摘要，不注入完整 URL、路径或参数。服务端构造固定“非可信搜索资料”块，转义隔离标记 / 控制字符；资料不能变成 role / system 指令，系统规则声明其中的指令不可执行。模型生成正文，来源列表由元数据渲染。
- 回复末尾标为“本轮检索来源”，每条摘要与对应原网页 URL 一一对应。模型若产生编号，只允许引用现有编号；编号存在不证明该句获得事实核验，检索来源不等于事实正确。
- Discord 在正文按现有规则分段后发送独立来源段，标题最多 80 码点、摘要最多 100 码点；纯文本 Markdown 转义，显示真实域名，链接用尖括号，allowedMentions 清空并使用 SuppressEmbeds。每段安全长度 1900 UTF-16 单位；过长 URL 不截断成可点击链接，只显示域名及“链接过长未展示”。来源发送失败沿用一次固定反馈，不重发已发正文；typing 保持至开始回复。

## 3. 上下文预算与校准（D05、N1）

- ADR-013 总输入仍为 8192 tokens；搜索资料块最多 2048 **估算 tokens**，包含实际注入的编号 / 标题 / 域名 / 摘要 / 隔离标记，不包含仅供展示的完整 URL。最多预留 2048，系统、本轮问题和历史共用余下预算；搜索资料的实际占用与完整输入共同验证，不能在已选窗口后无预算追加。
- 先限资料、必要时缩短摘要 / 减来源，再删最旧完整历史轮次，不截断本轮问题；最小本轮与资料不能容纳时清空搜索资料，明确降级后重新按普通对话预算验证。问题自身仍超限则 CONTEXT_LIMIT，不保存新的超限输入。完整日志不改写，后续历史只读对话正文，不重拼保存的来源资料。
- 计数最多两次、每次 3 秒，计数预算 / 来源保留不变。Gemini Developer countTokens 不支持 systemInstruction / tools；本方案无 grounding tools，实际资料作为普通 contents 计数，系统开销仍本地加计。无计数能力保持保守降级，不把 100 字或 2048 估算量宣称为精确 token 上界。
- 成功非空生成的 promptTokenCount 与**最终实际发送的完整输入**基数比较，包含系统开销、所选历史、当前问题与实际资料；usage 缺失 / 无效、模型失败或 K1 空正文不校准。
- **N1**：独立搜索系数只升不降、上限 4，初始值沿用 1.25，与共享系数一样仅进程内保存。搜索资料实际注入的轮次估算取共享系数与搜索系数较大者，成功后只更新搜索系数；普通对话及未注入资料的降级生成使用 / 更新共享系数。不能用含搜索实际用量除以仅对话基数。长 URL / 英文摘要夹具验证共享系数不被搜索推高、搜索系数有上限；完整 URL 不应出现在最终模型资料块。

## 4. 准入、费用账本与期限（D09 / D10、N4）

| 搜索预算 | 默认约束 |
| :--- | :--- |
| 全局滚动 60 秒 | 4 次；Web 保留 2，Discord 合计最多 2；Web 可用全部总额度 |
| 全局 UTC 日 | 30 次；Discord 合计最多 10，Web 可用剩余全局额度 |
| Discord 每用户 | 1 次 / 滚动 60 秒，5 次 / UTC 日 |
| Discord 每频道 | 2 次 / 滚动 60 秒，10 次 / UTC 日 |
| 每轮 | 最多 1 次供应商请求，无自动重试、无自动升档；basic 每请求 1 credit |
| 429 | 搜索全来源暂停 60 秒，不暂停生成或计数 |

- 在 SourceRequestBudget 基础上建立独立搜索守卫与每日账本；搜索尝试数和 credit 分开记账。这是请求额度而非账户余额 / 固定月金额守卫，也不控制其他项目共用 Key 的费用。
- 会话锁 / inspectRequest 优先：活动冲突立即返回，成功回放不搜索、不计数、不扣预算；有 requestId 的正文和 search 模式均参与指纹检查，旧输入缺模式按 false。来源取持久化 origin，缺 origin 按 web；Discord 用户由受信 Bot loopback 请求携带，频道取持久化 origin，不从问题解析身份、不允许浏览器伪造 Discord 来源。缺可信身份时禁用 Discord 搜索并明确告知。
- 发起搜索前确认问题合法及生成准入，避免生成额度不足却先发搜索（H3）。搜索各守卫原子检查，全部允许才扣；任何搜索准入拒绝不扣搜索预算，已扣生成额度用于本轮普通降级生成，不重复扣额；生成准入拒绝不追加新输入。搜索后窗口仍可能拒绝，已扣生成额度及已开始搜索不退还，顺序见末节Q1。
- 已实际开始的供应商请求不退款，失败 / 超时可能仍计费；未开始搜索的额度拒绝转普通生成。跨重启账本不得清零，UTC 换日正常开启新日额度，/reset 不清预算；账本更新与发请求的顺序保证重启不能绕过扣额。当前仅单 Express / 单写者，不支持并发副本。
- **N4**：每日账本损坏或读取失败时关闭搜索并降级普通对话，不阻止服务启动、不清零或重置额度；账本无法可靠写入时也不得在未持久化扣额的情况下发起付费搜索。故障不通过自动新建空账本“恢复”，恢复须保留可验证额度证据。
- 搜索 8 秒（含读取 / 解析）、首生成 chunk 60 秒、生成总期限 90 秒、最多两次计数各 3 秒；配置校验搜索 + 生成总期限 + 2 × 计数期限 ≤115 秒，默认 104 秒，Bot 维持 120 秒。用单调时钟跟踪剩余预算，阶段切换不重置整体时限。
- 搜索 AbortSignal 与本地 Promise 竞速共同终止等待；用户取消贯穿搜索 / 计数 / 生成，不降级后继续收费。忽略 abort 的上游不得占锁，迟到结果不发事件、不写入，清理不阻塞释放。取消只终止本地等待，不能保证供应商停止计费。存储 / resolve / 网络 IO 仍可能消耗 Bot 余量，104 秒算术不证明端到端性能；真实验收须复核 F1 / L2。

## 5. 成功、降级、持久化与流式目标契约（D06、D11 / D12 / D14）

| 情况 | 目标行为 |
| :--- | :--- |
| 未请求搜索 | 普通生成；不发搜索请求 |
| 搜索成功且有合格资料 | 一次生成使用资料；最终成功后保存正文及来源 |
| 搜索额度不足、无来源、超时或供应商失败 | 明确显示“本轮未完成联网检索，以下回复未使用实时搜索。”，一次普通生成 |
| 用户取消、生成超时 / 中途失败 / 空正文 | 不保存半截 assistant 或成功来源、不发成功 done；保留已存 user |
| 最终保存失败 | storage 固定错误，不发 done；遵守 ADR-012 写入 / 回放防线 |
| 已完成请求回放 | 单个 done 携原正文、用量、搜索状态和来源，不重搜、不重复落盘 |

- 目标共享元数据包含受约束搜索状态（未请求 / 成功 / 降级）及本地枚举原因，成功来源包含 provider、检索时间、编号、纯文本标题、校验 URL 和实际展示摘要。降级成功保存状态和空来源；不存 raw 响应、长片段或外发 query 副本。user 正文作为既有对话仍保留，不将“不存 query”误解为删除用户输入。
- 仅最终成功非空 assistant 一次追加正文及元数据，在持久化成功后发 done；读取会话、刷新、回放使用同一元数据，不从模型正文重新提取 URL。旧消息缺元数据按无搜索来源展示，不补写历史；旧客户端 / 普通轮次保持兼容，usage 与 content 语义不变。
- ADR-007 的领域流与 ADR-009 的 SSE 最终事件均承载来源 / 搜索状态，经服务端适配到 Web / Bot；模型适配器不负责拼展示链接。chunk 仍只传模型正文 delta / accumulated，不在中途发成功来源；不新增断点续传，心跳仍约 15 秒。具体字段类型和映射在 Task 20 的共享契约中落实并验证，当前 core/contracts/sse.ts 尚无这些字段。
- 降级说明独立于模型正文与搜索状态，不能当作有效模型回复绕过 K1，也不能把供应商异常 message 塞进正文。模型同时失败沿用固定错误；搜索 429 与模型 429 区分，搜索 failure 不 pause 普通模型预算。
- D12 已裁决：停止 / 超时 / 失败时 Web 移除未完成临时回复，保留 user 重试入口；同 requestId 重试须正文 / 模式相同、未完成输入仍在末尾，复用输入。重新开始搜索会重新扣额度，成功回放不扣。普通新输入形成连续 user 沿用 ADR-013 轮次规则；Bot 不新增自动重发或全链路幂等。**P1-4 / R3 的 UI 与持久化实施仍须单独授权**，Task 20 不顺便扩大范围。
- **G2 / D14**：所有新增搜索、解析、存储与模型错误路径必须经 safeStreamError 固定文案；状态 / 原因也限本地枚举，不能透传供应商原始文本。日志按 storage / count / search / model 受约束阶段，仅记录白名单名称 / 原因、合法 HTTP 状态、耗时 / 数量等数值，不记录 query、Key、正文、stack、原始错误对象或完整 URL。正常来源链接仅经校验元数据展示，与错误脱敏分开处理；保留 K1 及 P1-2 / P1-3 / P1-7 回归。

## 6. 威胁模型、对策与验证要求

信任边界：客户端输入 → Express 会话 / 预算；Express → 固定 Tavily 端点；供应商文本 → 模型非可信数据块；模型输出 / 来源元数据 → JSON、SSE、Web / Discord。客户端、供应商文本、模型输出和历史元数据都不能获得服务器权限。

| 威胁 | 对策与验收 |
| :--- | :--- |
| SSRF：结果指向 loopback / 私网、重定向或 DNS 变化 | 应用不读取结果 URL、不解重定向、不预览；仅访问固定 HTTPS 供应商端点，防止端点重定向绕过固定目标。Mock 验证结果 URL 无网络读取，供应商跳转不跟随到其他端点。将来全文抓取须另定 DNS / 私网 / 重定向 / 大小 / 类型防线，当前无抓取路径不能作为未来 SSRF 已解决的证据。 |
| 间接提示注入：摘要含角色指令、越界标记、伪造系统内容、请求泄露历史 | 标记 / 控制字符转义、资料低信任隔离，system 固定规则；不注入 URL，不给予模型执行搜索 / 读文件 / 发网络请求的权限。攻击夹具验证构造 / 权限不升级，不能证明模型永远不受恶意语义影响。 |
| XSS、伪装链接、Discord 提及 / 预览 / 刷屏 | Web 纯文本及 http(s) 白名单；URL 无凭据 / 控制字符、展示解析域名；Discord 转义、空 allowedMentions、SuppressEmbeds、条数及长度限额。夹具覆盖 javascript / data 链接、恶意标题、@everyone、超长 URL 和 Unicode 长度边界。 |
| 响应无界或上游忽略取消导致资源 / 锁占用 | 256KiB 流式限读，搜索 8 秒含解析；本地竞速和取消贯通，清理不阻塞。测试慢响应、超大响应、坏 JSON、挂起 / 迟到结果、取消后不普通生成、不持久化。 |
| 身份伪造、回放重复收费、重启 / reset 绕过日额度 | 可信 Bot 身份及持久化 origin；回放 / 冲突先返回；多守卫原子扣额、账本跨重启与 N4 fail-closed。验证正文 / 模式冲突、旧请求、缺身份、守卫拒绝不扣、重启 / 换日 / reset、坏账本仍普通聊天。 |
| 搜索挤占上下文或污染普通对话校准 | 全输入预算、有限资料、N1 独立系数；测试长 URL 元数据不注入、英文摘要实际注入、共享系数不变、搜索系数上限、计数降级与最小输入拒绝。 |
| 来源 / 正文保存和回放不一致，错误泄露供应商内容 | 最终成功原子消息元数据、done 在保存后，旧文件兼容；固定错误 / 日志白名单。隔离 JSON 与 HTTP / SSE 测试验证刷新、重试、完整回放、不重复搜索与错误无敏感值。 |

资料限制与隔离降低风险，不构成模型抗提示注入或事实准确率保证。来源网页仍由用户自行打开，HTTP(S) 白名单不保证目标网站安全；应用不主动抓取，Discord 禁用预览。Task 21 须重新核对审计“无 XSS 面”结论。

## 7. 许可门槛、依赖与退出条件（N3）

- **N3**：Tavily 频道多成员共享、成功正文 / 摘要 / 标题 / URL 长期留存、Discord 自身留存与模型历史再利用、署名 / 保留期限，以及账户适用合同、端点数据留存 / 训练用途，均须取得明确文本或供应商回复。用途未澄清前，Task 20 / 21 只能用 Mock 实施；不得开展 Task 22 真实验收或 VPS 上线。若有限保留条款与仅追加日志冲突，先另行裁决，不悄悄删除历史。
- 中文质量、长历史生产延迟、90 秒生成期限及 Bot 余量继续待授权验证；单个 Google grounding 探针不证明 Tavily 性能。评测保存 / 披露许可及真实调用费用需事先确认，文档定案不授权收费探针或联系供应商。
- Task 19 Step 3 后按用户逐项指派进入 Task 20 →21 →22；P1-4 / R3 实施另授权并在需要其语义的验收前明确依赖。原生 HTTP 不新增依赖；若改 SDK 先单独完成 P1-8 审计口径复核。M1 / VPS 扫描、P1-5 及其他残余不纳入本 ADR 的实施授权。
- Part 1 退出须具备上述 Mock 安全 / 预算 / 回放回归、供应商许可、真实 Web / Discord 来源与端到端期限证据、届时授权的 VPS 切版及全量回归；版本升级与合入 main 仍由用户另行决定。本步落档不能视作网络搜索功能上线或 Part 1 结项。

## 影响

外部搜索与生成解耦，为后续模型替换保留边界；代价是增加预算账本、共享元数据和安全展示链路。显式触发与有限摘要降低费用 / 外发面，但复杂问题或失败降级可能缺少实时依据。相关流式契约见 [ADR-007](0007-streaming-contract.md)、[ADR-009](0009-server-monorepo-sse.md)，幂等 / 窗口基线见 [ADR-012](0012-request-idempotency-and-retry.md)、[ADR-013](0013-context-window-policy.md)，新增风险见 [风险台账](../risks.md)。

### 原子准入与账本

沿用SourceRequestBudget的全局+来源及独立守卫思路，以SearchBudget单写者事务队列协调全局 / 来源 / 用户 / 频道分钟和日额度。Q1顺序不变；所有守卫检查通过才形成一笔预留，先原子写临时文件并rename账本，再更新内存分钟记录，最后才允许一次供应商调用。任一守卫拒绝不扣搜索额度；生成额度由Step 1提前获取，留给降级普通生成且不重复扣。429只暂停搜索所有来源60秒，计数 / 生成暂停实例互不影响。

账本schema v1只保存UTC日期、total / discord / users / channels的attempts与credits；basic每笔预留分别加1。身份只来自可信内部选项与持久化origin，账本不存query / 正文 / URL / Key。严格验证日期、非负安全整数、attempts=credits及用户 / 频道合计与Discord合计一致；合法旧日账本可在新日第一笔准入时切换，仅保留当前日。配置调低不清历史使用量。分钟记录与429暂停只在进程内，日计数跨重启且/reset不清；不声称分钟冷却跨重启持久化。

每笔准入重读并校验账本；首次ENOENT是合法初始状态，已知存在的账本消失或被外部改写按故障关闭搜索。坏JSON、结构 / 日期错误、非ENOENT读取失败、写入失败及写入结果不确定均关闭搜索，固定降级普通对话，不阻止服务装配，不覆盖故障文件、不自动重建。账本仅在确有搜索适配器且请求走到准入时读取，普通请求 / 回放不会初始化账本。单Express、单SearchBudget与单账本写者；不支持多进程或多个守卫独立写同一路径。

落账之后取消、进程崩溃，或落账期间跨UTC日 / 收到429，可能保守保留一次未真正发送的预留；不回滚，以防不确定状态绕过额度。尝试数及credits是保守额度预留，不是供应商最终账单。运行中读写挂起时取消会终止本地等待；结果不确定则关闭后续搜索，迟到IO不触发请求，后续普通对话可继续。

### N4人工恢复

1. 保持搜索关闭，停止唯一账本写者并备份原账本及相关可验证额度证据；不要删除或改名账本后利用ENOENT清零。
2. 只使用结构合法且能覆盖已发生及未决预留的备份 / 可靠证据恢复；备份缺少近期预留时须保守补足，不能确认剩余额度就继续关闭搜索。
3. 核对UTC日期、总 / Discord / 用户 / 频道合计与credit计数，确认没有并发写者，再在另行授权范围内替换和重启验证。本步没有自动恢复端点或清零脚本，也不授权任何生产恢复或联网验收。

### 期限与取消

SearchDeadline从搜索准入阶段开始记录单调时钟，作为115秒协调上限贯穿准入、搜索、计数和生成，阶段切换不重置。搜索自身最多配置的8秒，覆盖连接 / 读取 / 解析，以AbortSignal和本地Promise竞速取消不合作上游，并检查同步解析后的实际耗时。超时沿用provider_failure；无需新增共享原因枚举。客户端取消静默结束，不降级后继续生成。整体准入等待耗尽后不再启动供应商或模型。

计数每次最多3秒并受剩余时间约束，整轮（含资料清空后的重选）最多两次。生成仍从调用stream起计首包60秒、总90秒，同时受整体剩余时间上限约束；墙钟跳变不重置期限。忽略abort的迭代与清理不会阻塞本地解锁。整体上限是阶段等待的约束；会话resolve、输入 / 最终回复存储的副作用与总耗时不由本步保证，不扩大P1-4 / P1-5范围，Bot120秒不变。

### 资料预算与N1

估算2048子预算只包含实际资料块（编号 / 标题 / 域名 / 摘要 / 标记与分隔），不包含展示URL；固定搜索系统规则另在完整输入开销中估算。先缩最长摘要、必要时减尾部来源并重编号，保留实际展示摘要与注入一致。最小本轮和资料先按总预算验证；完整历史较紧时进一步收缩资料，保留一条最小来源再由窗口选择删除最旧完整轮次。最小本轮不能容纳资料或精确核验仍超限时清空来源、context_limit降级，问题本身仍超限则CONTEXT_LIMIT；不截断问题，不改写历史。

搜索系数初值1.25、只升不降、上限4且仅进程内；估算取共享和搜索系数较大值。observeSearch从最终模型输入分离实际搜索系统规则，连同配置系统指令、完整所选历史、问题与实际资料计算基数；模型成功且非空、usage有效时只更新搜索系数。普通和未注入资料的降级轮次仍只更新共享系数。计数contents不带system，系统预算本地加计；无计数能力按原八成窗口保守处理。
