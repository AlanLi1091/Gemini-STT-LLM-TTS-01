# 风险与阻塞

- **风险 0（已发生，已缓解）**：agent 完成偏置导致越权执行。
  - **事件**：首次会话中 agent 跳过文档与仓库初始化，直接编写前后端代码。
  - **应对**：v2 铁律与授权机制（ADR-004）；任务票式指派；保持工具逐条确认模式。
- **风险 1**：React 19 与测试库兼容性。
  - **应对**：使用适配 React 19 的最新 Testing Library 与 Vitest，jsdom 环境。
- **风险 2**：无头环境 DOM 滚动。
  - **应对**：jsdom 中显式 Mock `Element.prototype.scrollIntoView`。
- **风险 3**：密钥管理（Phase 3 起）。
  - **应对**：token / API key 不入 git；.env + .gitignore；密钥仅存在于服务端。
- **风险 4**：STT→LLM→TTS 串行延迟（Phase 6）。
  - **应对**：流式传输与管道并行化；先验证端到端延迟预算。
- **风险 5**：Discord API 限流（Phase 4）。
  - **应对**：依赖 discord.js 内置限流处理；设计消息频率上限。
- **风险 6**：token 与 TTS 成本。
  - **应对**：Phase 2 起记录用量；Playground 默认 Mock / 低成本模型。
- **风险 7**：AI Studio 沙箱无凭证导致 GitHub 远端 Push 校验中断。
  - **事件**：执行环境为 Google AI Studio，其沙箱未预置 GitHub 交互式凭证/PAT，非交互执行 `git push` 报 `could not read Username`。
  - **应对**：确保本地具备完整语义化 commit 链路；待环境配置 PAT 或由用户在设置中授权同步。push 失败属已知环境限制，记录后继续推进，不视为步骤失败。
- **风险 8**：@google/genai 浏览器兼容与版本变动。
  - **应对**：锁定版本、SDK 类型不泄漏进领域内核。
- **风险 9（已发生，已缓解）**：Gemini API 403 权限/环境异常与密钥清洗防御。
  - **事件**：用户使用未启用付费/欠费/项目受限的 API Key 发起调用时返回 403 PERMISSION_DENIED。
  - **应对**：排查确认为环境/Key 权限问题；同时沉淀四重通用防御（不可见字符与空白清洗、空 key 拦截、强触发重构），确保前端链路无隐形故障。
- **风险 10（已发生，已缓解）**：本地跨平台执行环境（macOS ARM64）与 Rollup 原生依赖适配。
  - **事件**：本地 Apple Silicon 环境运行 Vitest 时，因 node_modules 仅包含 x64 版本、缺少 `@rollup/rollup-darwin-arm64` 原生二进制可选依赖，导致测试引擎在收集测试前启动失败。
  - **应对与红线**：仅限在本地机器依赖目录修复补齐；严禁将特定平台的二进制依赖或平台污染的 `package-lock.json` commit / push；修复后本地 13/13 套件、118/118 用例通过。`package-lock.json` 在本地保持未跟踪，并由 `.gitignore` 忽略，作为当前既定政策。未来部署实施若需要 lockfile，须在受控 Linux/CI 环境生成干净版本后，再经单独授权移除忽略规则并提交。
- **风险 11（已发生，待 AI Studio 恢复）**：Google AI Studio 重复出现 “Internal Error” 导致 Gemini 3.8 Flash 侧开发流程中断。
  - **事件**：用户反馈该错误持续出现且并非个例；Google AI Developers Forum 近期公开报告了 Gemini 3.8 Flash / AI Studio 的重复性 Internal Error（[2026-09-08 报告](https://discuss.ai.google.dev/t/repeated-an-internal-error-occurred-in-google-ai-studio-build-with-gemini-3-8-flash/181795)、[2026-09-14 报告](https://discuss.ai.google.dev/t/gemini-3-8-flash-down-an-internal-error-occurred-tool-calling-and-web-access-not-working/182668)）。
  - **应对与交接**：GPT-5.6 Sol 临时接替开发；待 AI Studio 恢复后，GPT-5.6 Sol 的开发任务暂时终止，由 Gemini 3.8 Flash 继续开发。该交接不改变 Phase 3 路线、任务边界或当前授权。
- **风险 12（已发生，已缓解）**：Vite 自动递增端口可能占用 Express 后端端口并造成代理 500。
  - **事件**：3000 已存在 Vite 时重复运行 `npm run dev`，新 Vite 自动选择 3001；此时前端 `/api` 的默认代理目标也是 3001，导致请求进入第二个 Vite 而非 Express，并返回 HTTP 500。
  - **当前应对**：Vite 开发脚本已增加 `--strictPort`，3000 被占用时立即失败，不再自动递增并占用 Express 的 3001；本地仍保持单一 Vite 运行于 3000，先确认 3001 未被占用后运行 `npm run server:dev`。可用 `lsof -nP -iTCP:3000 -sTCP:LISTEN` 与 `lsof -nP -iTCP:3001 -sTCP:LISTEN` 核对进程类型。
- **风险 13（已识别，待修复）**：Phase 4 结项后代码与安全审计遗留。
  - **事件**：2026-10-06 只读审计（基线 `f98920d`）未发现当前私有 loopback + SSH 隧道拓扑下可被外部直接利用的高危漏洞，但识别 P0 3 项、P1 8 项、P2 5 项、P3 13 项；P0-2 重试重复持久化用户消息、P1-1 客户端可写入 system 角色、P1-3 存储错误误报为网络错误已实测复现。
  - **应对**：全文与修复建议见 [审计报告](research/phase4-code-security-audit.md)；修复项登记于 `backlog.md`「审计修复」任务组，须逐项授权。P2 为任何公网暴露 / 多用户授权的前置条件。审计未覆盖 VPS 实际配置与动态测试，结论不涵盖这些面。
  - **P0-3 已缓解（2026-10-06）**：用户单独授权并确认计划后，开发脚本默认改为 `--host=127.0.0.1`；实际监听 / 首页 / 隔离 Mock 代理验证 3/3、全量 305/305 用例与类型检查通过。显式覆盖 host 仍可主动开启局域网访问；P0-1、P0-2 与其他审计项待授权。

- **风险 13 / P0-2 已缓解（2026-10-06）**：单独授权的 Web 重试路径已使用稳定 UUID；复用输入、完整回放与写入队列防重复输入 / 回复均有回归覆盖。会话锁覆盖旧请求及 Bot，停止后立即重发可能短暂 REQUEST_CONFLICT，Web 固定提示并允许手动重试。单 Express / 单存储实例约束保留，无标识请求的重发与历史重复日志不自动修复；P1-4 半截回复持久化、P0-1 历史预算与其余项仍待授权。详见 [ADR-012](adr/0012-request-idempotency-and-retry.md)。

- **风险 13 / P0-1 第一步已缓解（2026-10-06）**：模型视图默认受 8192 输入预算、20 历史轮次与 8192 生成上限约束；本地估算 / 边缘计数 / 失败收缩避免全量历史增长，完整持久化日志保留。估算不是数学上界，系统文本本地加计；当前 SDK 的 Developer countTokens 拒绝 systemInstruction 已离线确认。MAX_TOKENS 提示随正文保存并进入后续窗口；空正文不保存助手回复。计数器次数 / 超时有界、校准系数内存限幅。Discord 重置与归档锁第二步未授权，JSON 文件增长、P1-4 半截回复及其余项未处理，P0-1 整项保持未完成；详见 [ADR-013](adr/0013-context-window-policy.md)。

- **风险13 / Claude C1已修复、C2降级取舍明确（2026-10-06）**：修正计数前硬裁且不可加回的问题，候选取样后按观测比率选择并核验，计数仍最多两次；三组近似夹具保留8 / 11 / 9轮、预算利用率87.8% / 88.1% / 92.4%。C2无精确计数时记忆可能缩短已写入部署说明，估算无数学上界承诺；未扩展Discord重置或其余审计范围。

- **风险13 / P0-1第二步代码修复完成（2026-10-06）**：管理员名单校验与精确命令、明确旧目标归档 / resolve、新关联确认 / 失败自然恢复、全路由共享服务和归档锁已实现；R1冲突可读提示同步覆盖。旧日志保留，HTTP目标重复不归档新会话，命令沿用FIFO / 冷却。管理员默认空须上线另行配置；内部API依赖loopback / 无Origin边界，取消不回滚已发生归档，挂起上游强制解锁仍属于P1-2。P0-1两步代码闭环，VPS尚未部署；P1 / P2 / C3–C5未扩展，见 [ADR-014](adr/0014-discord-session-reset.md)。


- **风险 14（已识别，实施与验收待授权）**：外部搜索间接提示注入及来源链接展示。
  - **边界**：供应商摘要 / 标题可能伪造角色指令、隔离标记或引用；模型可能受恶意语义影响，HTTP(S) 来源也不保证目标安全。引入链接后需重新核对既有“无 XSS 面”结论。
  - **对策**：[ADR-015](adr/0015-external-search-architecture.md)规定非可信资料隔离、标记转义、只注入编号 / 标题 / 域名 / 最多 100 字摘要；URL 仅校验元数据展示，Web 纯文本与协议白名单，Discord 转义 / 抑制提及与预览 / 限长。应用只访问固定供应商端点、不抓取结果或解析跳转；端点重定向不得绕过固定目标。未来全文抓取须另定 SSRF 防线。Mock 攻击夹具验证权限不升级，不宣称模型绝对抗注入或来源事实自动核验。

- **风险 15（已识别，实施与验收待授权）**：搜索费用、持久化账本及端到端期限。
  - **边界**：失败 / 超时搜索仍可能计费，重启或坏账本可能绕过日额度；搜索与生成耦合后可能耗尽 Bot 120 秒余量，预算估算不保证真实 token 上界或账户费用。
  - **对策**：搜索独立分钟 / UTC 日 / 来源 / 用户 / 频道预算，每轮一次 basic、无重试；发请求前确认生成准入及原子扣额，完成回放不收费，/reset 不清日额度。N4 坏账本关闭搜索、普通聊天继续、不清零；不能可靠持久化扣额时不发付费请求。N1 独立搜索系数限幅，完整输入 8192 / 资料最多 2048 估算 tokens；8+90+2×3=104≤115 秒只属配置约束，Task 22 须实测 IO 与生产延迟。全部错误固定文案，Mock 验证重启 / 换日 / 取消 / 迟到 / 降级。

- **风险 16（许可与证据待补，真实验收 / 上线阻塞）**：查询外发第三方及搜索内容共享 / 长期留存用途。
  - **边界**：Tavily 频道多成员共享、正文 / 摘要 / 标题 / URL 长期留存、Discord 自身留存、模型历史再利用与署名 / 保留期，以及账户适用合同和端点数据留存 / 训练条件尚未澄清；选择供应商不等于已获许可，不能承诺 ZDR。当前问题本身可能含个人信息，自动过滤不能保证全部识别。
  - **对策**：显式逐轮触发、Key 仅 server.env、仅外发当前问题≤500码点，不发历史 / system / 身份信息，入口明确告知供应商与频道可见性。N3：用途澄清前 Task 20 / 21 只用 Mock，Task 22 真实验收与 VPS 上线不得进行；若有限保留条款与仅追加日志冲突，先另行裁决。中文评测保存 / 披露与调用费用也须确认；联系供应商、真实 API 探针均需另行指派。本轮仅落档，没有外发查询或部署。
