## 1. 问题
bot/search-sources.ts 的 formatSearchSources 在以下两种情况下，统一回退为：
  本轮检索来源
  <编号>. <域名>
  链接过长未展示
- URL 无效（如 javascript:、data:、带凭据、含空白或控制字符）时，"链接过长"的说法不实；
- 两种情况下都丢弃了本可安全展示的转义标题和摘要（Web 侧同样情形仍显示标题与域名）。

## 2. 修正要求
1. 回退时保留与正常情况相同的转义标题（最多 80 码点）、解析后的真实域名和转义摘要（最多 100 码点），只去掉 <URL> 那一行，改为按原因区分的固定说明：
   - URL 本身合法但会使整条消息超过 1900 个 UTF-16 单位："链接过长未展示"
   - URL 未通过校验（协议、凭据、空白 / 控制字符、非法 host、超过 2048 字符等）："链接无效未展示"
   域名无法解析时沿用现有的"域名无效"。
2. 回退消息本身也必须不超过 1900 个 UTF-16 单位：如果标题和摘要转义后仍会超长（例如超长 hostname 场景），按"先缩短摘要、再缩短标题"的顺序收缩，收缩后再转义并重新计算长度；不得截断出半个转义序列或拆开代理对。
3. 正常路径（URL 合法且不超长）的格式和行为不变；转义规则（Markdown、[ ] ( )、尖括号全角化、正文 https:// 改写）不变；SuppressEmbeds、空 allowedMentions、最多 3 条、独立消息的发送方式不变。
4. 不改 Web 侧、服务端或共享契约。
